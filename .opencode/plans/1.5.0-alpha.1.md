# v1.5.0-alpha.1 — Android Text Input Fix

## Summary
Fix `GetCharPressed()` returning 0 on Android by patching raylib 5.0's `rcore_android.c`.

## Problem
- `GetCharPressed()` always returns 0 on Android because `charPressedQueue` is never populated
- Desktop (GLFW) has a `CharCallback` that fills this queue; Android has no equivalent
- Two underlying bugs in `rcore_android.c`:
  1. Gamepad source flag collision — devices that set both `AINPUT_SOURCE_KEYBOARD` and `AINPUT_SOURCE_GAMEPAD` (same class bit) have keyboard events eaten by the gamepad handler
  2. No JNI call to convert raw keycodes to Unicode codepoints

## Solution
Patch `rcore_android.c` (applied via CMake after FetchContent_Populate):
1. Add `!(source & AINPUT_SOURCE_KEYBOARD)` guard to gamepad check (from upstream PR #5441)
2. Inside `ACTION_DOWN`: construct Java `KeyEvent` via JNI, call `getUnicodeChar(metaState)`, push to `charPressedQueue`
3. Only active when `cursorEnabled` (text input mode)
